# Shrunk 8×8 fabric validation (V1–V3) — issue #16 pre-harden gate

Issue #16 requires, **before** chip-level Harden A/B: program the shrunk Caravel-target fabric
with ≥1 real user design and verify it by behavioral **and** gate-level simulation. This records
that gate: **GREEN** (all required checks pass). Everything here is provider-neutral: the designs
are driven through `chip_top`'s generic serial contract (and the FABulous oracle's parallel
SelfWrite path), not through anything Caravel-specific.

|---|---|---|---|---|
| `lfsr8` | 8-bit maximal Fibonacci LFSR — the canonical stochastic-bitstream source | 11 (4%) | 16 (100%)¹ | 80.0 MHz |

| V3 gate-level, Verilator 2-state `#1`-delay | DIDNOTCONVERGE² | **PASS 200/200** | same netlists; result is not delay-model-specific |

² lfsr8 aborts with `%Error-DIDNOTCONVERGE` under both delay flags (and at `--converge-limit
500000`). Mechanism: the fabric's switch matrices form **structural combinational cycles**
(Verilator flags 36 `UNOPTFLAT` circles, e.g. through `Tile_X1Y1_LUT4AB.*.mux_4to20_out_X`) —
inherent to FPGA routing graphs. Under shiftreg8's configuration the cycles are logically
quiescent (sim converges); under lfsr8's configuration one is active and oscillates. The same
active loop parked at X explains lfsr8's *fully-X* outputs under icarus. lfsr8's behavioral
function (V2a/V2b) passes fully; whether its FASM genuinely routes a closed loop (which would be
a power concern in silicon and possibly a nextpnr/FABulous routing-graph question) is flagged as
a follow-up. lfsr8 is the informational design for V3; shiftreg8 is the required witness.

## Two testbench-methodology findings (the actual debugging yield)

1. **Posedge-write race (fixed; root cause of 8 "mismatches"):** the first TB drove the serial
   input with a blocking write in the *same timestep* as the sampling posedge. The behavioral
   golden and the gate netlist may legally sample opposite sides of that write — observed as a
   single wrong bit entering the shift chain and walking through (`sr[5]→sr[6]→sr[7]`), 8
   transient mismatches, exact steady-state match. Fix: **drive all stimulus at the negedge**
   (half-period setup). The upstream FABulous demo TB never exposes this because its inputs are
   held constant for many cycles. With the race fixed, shiftreg8 passes 200/200 at **both**
   zero-delay and `#1`-delay — there was never a netlist timing problem.

2. **icarus (4-state) cannot pass this netlist family** — confirmed and extended from the prior
   session's VCD-traced finding (idle `FrameStrobe`/`FrameData` X → gate `dlxtp` loses config
   where behavioral `config_latch` holds). Today's variant signature: with config apparently
   loaded (`T_top` fully correct), the datapath shows **every '1' correct, every '0' reads X**
   (an OR-branch X leak: `1|X=1`, `0|X=X`, through ABC-flattened routing muxes). Falsified
   fixes, kept for the record: `UNIT_DELAY=#1` + 100 ns clock (identical X),
   `tests/sky130_sim_prims_init0.v` (defined power-up state on all storage UDPs — bit-identical
   X), `-Wall` (no implicit nets). This is simulator semantics, not a netlist defect: the same
   netlist is exact under Verilator, and the layout matches it by LVS.

## Engine decision

**V3 engine = Verilator (2-state), functional sky130 models, race-free negedge TB, zero cell
delay** (pure cycle semantics; uniform `#1` would misrepresent relative timing anyway — the
netlists contain thousands of deliberately-slow `clkdlybuf4s25` hold buffers and the flow emits
**no SDF** — and empirically changes nothing here). icarus stays the engine for V1/V2
behavioral only.

## Conclusion

The issue #16 pre-harden validation milestone is met: the shrunk 8×8 Caravel-target fabric is
**programmable with real bitstreams** (V1, reproducible bit-identically), **functionally correct
behaviorally** through both the oracle path and the `chip_top` serial contract (V2a/V2b, two
designs), and **functionally correct at gate level** on the post-layout netlists (V3, shiftreg8,
200/200 under two delay models). **Chip-level Harden A/B is unblocked.** Follow-ups: lfsr8's
active routing-loop question (informational; possibly upstream-relevant), SDF/timing-true GL sim
(belongs to the macro `.lib` / timing follow-up issue).
